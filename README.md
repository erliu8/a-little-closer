# 再近一点？ · A Little Closer?

一个围绕 Shift、距离和回应的中文互动短篇。首章《末班车前的一只耳机》可以从开场玩到两个不同的结局。技术栈为 TypeScript、Vite、Canvas 2D 与 Web Audio，运行时资源随游戏一起分发。

## 本地游玩

使用 Node.js 24 或更高版本，在项目根目录执行：

```sh
# 首次安装或锁文件发生变化时安装开发依赖。
npm ci

# 打开终端显示的本地地址。
npm run dev
```

点选对白推进剧情。进入动作时，按住 Shift 在轨道上左右拖动，或按 Shift 加左右方向键；触屏直接拖动。圆点代表你，竖线代表她，亮区表示这一刻适合停留的位置。切出页面会暂停当前动作，回到页面点击“继续”。右上角可开启合成旋律。

## 项目结构

| 位置 | 职责 |
| --- | --- |
| `src/game/story.ts` | 定义场景、对话选项、移动窗口、动作结果与结局的数据契约。 |
| `src/game/engine.ts` | 维护一局的状态，接收选择、位移和活跃时间。无浏览器、文件系统或网络依赖。 |
| `src/stories/station.ts` | 首章的对白、选择、场景引用、节奏参数和两条结局。 |
| `src/assets/` | 用代码绘制的站台背景和像素人物。 |
| `src/ui/` | 轨道输入、Canvas 舞台、声音与响应式界面样式。 |
| `src/main.ts` | 装配故事和浏览器界面，管理暂停与重玩。 |
| `tests/game.test.mjs` | 覆盖真实首章的两条结局、超时、过快、越界、失误恢复与跨场景。 |

## 增加剧情与场景

**同一场景里续写。** 在 `nodes` 中新增唯一的节点 ID，把现有选项的 `next` 指向该 ID。普通对白使用 `kind: 'dialogue'`，动作使用 `'movement'`，落幕使用 `'ending'`。选项的 `affection` 可增减好感，`minAffection` 控制可见条件。可把新章节放进独立文件，按 `Story['nodes']` 声明节点集合，再用对象展开放入故事，节点 ID 应在整部故事中唯一。

**进入新场景。** 在故事的 `scenes` 中登记一个 ID 和标题，在 `src/assets/` 写对应的背景绘制函数，并在 `src/ui/stage.ts` 的场景表中用相同 ID 注册画法与画面描述。在首个新节点设置 `scene`，后续节点沿用该场景。举例，下面是可从已有选项连接到的“车厢”结局，配套场景登记后即生效。

```ts
// 放进故事的 nodes，前一个选项的 next 设置为 'carriage-seat'。
'carriage-seat': {
  kind: 'ending',
  scene: 'carriage',
  speaker: '她',
  text: '她往窗边挪了一个座位，把另一只耳机放在你手心。',
},
```

**调动作手感。** `range` 是目标区间，`limit` 是向前越界线，单位都是整条轨道的百分比。`relative: true` 表示从进入动作时的位置量起。`maxSpeed` 以轨道百分比每秒计，`holdMs` 和 `durationMs` 用毫秒。三个结果 `success`、`rushed` 和 `late` 各自指定下一节点和好感变化。加章节时，给新增分支留一项通过真实选项到达结局的测试。

## 检查与分发

```sh
# 测试直接执行 TypeScript 规则模块。
npm test

# 做类型检查并输出静态文件至 dist/。
npm run build

# 从本机 HTTP 服务试玩构建版。
npm run preview
```

**网页分发。** 上传 itch.io 时将 `dist/` **里面的文件**打包成 ZIP，确保 `index.html` 位于压缩包根目录，项目类型选 HTML。开发依赖留在本机。

**后续做桌面软件。** 桌面壳可以通过应用内本地协议或本地静态服务加载同一份 `dist/`。Vite 已配置相对资源路径。选用 Tauri 或 Electron 时，可沿用剧情、规则、画面与输入，只需新增宿主入口和打包配置。当前交付为可玩的网页版。

**素材与制作。** 本版剧情、程序绘制的背景和角色、合成旋律以及代码均使用 AI 辅助制作。所有运行时视听素材都在源码中，提交 Game Off 时应按比赛表单披露实际使用情况。
